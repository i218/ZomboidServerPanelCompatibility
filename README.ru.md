# ServerPanelBridge

Отдельный мод для Project Zomboid Build 42: передаёт состояние dedicated server в ServerPanel через ZombieBuddy.

[English version](README.md)

## Что показывает панель

Сервер появляется в категории **Game servers**. Каждые пять секунд обновляются:

| Показатель | Значение |
| --- | --- |
| Online | Панель недавно получила heartbeat |
| Health | Healthy, пока работает серверный цикл, включая паузу пустого сервера; Degraded после 20 секунд без отклика |
| CPU | Нагрузка процесса JVM с нормализацией по логическим процессорам |
| Memory | Используемая Java heap в МиБ, не вся память процесса |
| Uptime | Время работы JVM |

Online и Degraded могут отображаться одновременно: фоновый отправитель работает, но игровые тики остановились. После завершения процесса или потери связи панель помечает сервер как offline.

Отправка работает в фоне. Недоступная панель не задерживает игровой поток. Таймаут запроса — две секунды, задержка повторов увеличивается до 30 секунд. Связь восстанавливается автоматически.

Этот выпуск реализует **мониторинг, отправку Output, команды с привязкой к сеансу, штатную остановку и перезапуск по явному разрешению**. Start требует внешнего управления процессом. Для игроков и обновлений Workshop в API панели ещё нет отдельных полей.

## Один установщик

1. Закрой игру и dedicated server.
2. Запусти **ServerPanelBridge-Setup.exe**. Админка обычно не нужна.
3. Укажи фактическую папку данных Zomboid (cachedir) серверного пользователя и выбери существующий сервер.
4. Оставь включённой настройку dedicated server. Если составляешь серверный INI через клиент, можно отметить включение в клиентском списке модов.
5. Нажми «Установить», затем запусти сервер и ServerPanel на той же машине.

В EXE уже встроены мод и собранный JAR. Установщик распакует файлы, добавит ZombieBuddy и ServerPanelBridge в выбранный INI, создаст отсутствующий runtime-конфиг и проверит записанные файлы. Существующий конфиг и остальные настройки сохраняются. Резервные копии — в `<cachedir>/ServerPanelBridge-installer-backups/`. При ошибке записи выполняется откат.

ZombieBuddy Java agent должен быть установлен заранее; ServerPanel устанавливается отдельно. Установщик не запускает и не останавливает приложения, не меняет WorkshopItems и не обходит доверие ZombieBuddy. JAR остаётся неподписанным.

По умолчанию установка только серверная. Клиентская галочка необязательна: она включает этот же локальный мод в `mods/default.txt`, чтобы удобнее было составлять настройки через игру.

**Подключающимся игрокам ServerPanelBridge не нужен.** После загрузки адаптер удаляет только его запись из списка обязательных клиентских модов Build 42; серверный код и остальные моды сохраняются. Если API несовместим, в логе будет ошибка. Реальное подключение без мода ещё нужно проверить на сервере. Требования самого ZombieBuddy к клиентам остаются прежними.

Для автоматической установки:

```powershell
.\ServerPanelBridge-Setup.exe --silent --data-dir "D:/PZData" --server-name "servertest" --mode server
```

Режимы: `server` (по умолчанию), `client`, `both`. Успех — код 0, ошибка — код 1 и диагностический файл в Windows Temp. Для пути используй фактическую папку, не junction/symlink.

Ручная альтернатива: распаковать **ServerPanelBridge-mod.zip** в `<cachedir>/mods/` и добавить мод после ZombieBuddy в `Mods=`. Предмет Steam Workshop пока не опубликован.

## Настройки

При запуске dedicated server мод создаёт:

```text
<Zomboid cachedir>/ServerPanelBridge/<имя сервера>/ServerPanelBridge.properties
<Zomboid cachedir>/ServerPanelBridge/<имя сервера>/ServerPanelBridge-0.log
```

Путь cachedir берётся из игры, включая пользовательский `-cachedir`. Логи занимают до трёх файлов по 1 МиБ. Меняй настройки при остановленном сервере и затем перезапускай его.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| enabled | true | false отключает отправку |
| panelUrl | http://127.0.0.1:5088 | Только локальная панель на той же машине |
| hostId | pz-<имя сервера> | Уникальный постоянный идентификатор |
| hostName | Project Zomboid: <имя сервера> | Имя в панели |
| category | Game servers | Категория |
| environment | Production | Подпись среды |
| address | Local dedicated server | Подпись, не адрес подключения |
| heartbeatSeconds | 5 | Интервал 5–10 секунд |
| requestTimeoutSeconds | 2 | Таймаут 1–5 секунд |
| staleTickSeconds | 20 | Когда считать игровые тики устаревшими |
| maxRetrySeconds | 30 | Максимальная задержка повтора |
| outputEnabled | true | Передавать события моста во вкладку Output |
| captureConsoleOutput | false | Также передавать Java stdout/stderr; возможны приватные данные |

[Пример конфига](config/ServerPanelBridge.properties) в архиве — справочная копия. Активный конфиг создаётся автоматически в cachedir.

При выключенном захвате консоли мост не читает списки игроков, чат, INI или чужие файлы логов. Захват консоли включается отдельно и не скрывает персональные данные или секреты.

## Проверка после установки

1. Дождись появления сервера в панели.
2. Проверь изменение CPU, памяти и uptime.
3. Закрой ServerPanel, оставив сервер работать. В логе появится предупреждение о связи, игра продолжит работу.
4. Снова запусти панель. Heartbeat возобновится автоматически.
5. Штатно останови dedicated server. После истечения окна свежести heartbeat панель покажет offline — сейчас это 15 секунд.

Для проверки не нужно принудительно завершать процесс. Чтобы отключить отправку, поставь `enabled=false` и перезапусти сервер.

Нужны JDK 11 или новее и Gradle 8.7:

```powershell
.\gradlew.bat --no-daemon clean build installer
```

Единый установщик: `build/distributions/ServerPanelBridge-Setup.exe`.

Архив с готовым JAR: `build/distributions/ServerPanelBridge-mod.zip`.

## Локальные моды и MLOS (0.1.2)

Клиентская галочка в этом же установщике автоматически ставит и включает ServerPanelBridgeMenu. Он сохраняет установленный локальный ServerPanelBridge при записи настроек через MLOS, не подставляя выдуманный Steam Workshop ID. Обработка отсутствующих модов и опубликованных предметов остаётся у MLOS. После обновления перезапусти игру; компонент меню должен быть включён в главном списке модов.

ServerPanelBridgeMenu не добавляется в серверный INI. Его Lua хранится отдельно от основного мода, чтобы сохранить необязательность клиента при включённых checksum. Обе папки создаёт установщик, вручную раскладывать ничего не нужно. Для ручной установки компонент из client-support/ServerPanelBridgeMenu нужно скопировать в клиентскую папку mods и включить там.

Ошибки UnknownFormatConversionException в переводах настроек других модов — отдельная проблема. Этот компонент не содержит переводов или панели настроек.


## Штатная остановка (0.2.0)

Команда Stop для хоста теперь обрабатывается через очередь панели. В активном ServerPanelBridge.properties нужного сервера выстави:

```properties
commandsEnabled=true
stopEnabled=true
stopWhenPlayersOnline=false
```

После изменения перезапусти dedicated server. Установщик сохраняет существующий конфиг. По умолчанию commandsEnabled=true, но stopEnabled=false: без явного включения команда получает отказ.

Опрос команд идёт каждые пять секунд в отдельном потоке. Остановка вызывается на игровом потоке через проверенный публичный API Build 42 ServerMap.QueueQuit(). Затем игра выполняет штатное сохранение и выход.

При stopWhenPlayersOnline=false сервер с игроками отклоняет команду; причина передаётся в панель. Для явного разрешения остановки занятого сервера используй stopWhenPlayersOnline=true.

Успешное подтверждение означает «остановка запрошена», а не доказательство завершения сохранения или выхода процесса. Далее хост должен стать offline. Процесс может завершиться раньше отправки подтверждения; журнал защищает следующий запуск сервера от повторного исполнения этой команды.

Start получает отказ: запуск завершённой JVM нужен со стороны управления процессами ServerPanel или другого супервизора. Restart поддерживается встроенным помощником, как описано ниже. commandsEnabled=false отключает опрос команд; enabled=false отключает отправку и опрос панели; явно разрешённые локальные запросы модов остаются доступны. Сервер не завершается через kill или System.exit. В Windows фиксированный запрос PowerShell/CIM читает параметры запуска; произвольных shell-команд в конфиге нет.

Журнал хранится в commands/ рядом с runtime-конфигом, до 1 000 результатов, без lease-токенов. Команды с неизвестным результатом автоматически не повторяются. После проверки состояния сервера можно отправить новую команду. При обновлении журнал сохраняй.

## Необязательный мод на клиенте (0.2.1)

Обнови сервер новым установщиком и полностью перезапусти dedicated server. Обычным игрокам не нужны ни ServerPanelBridge, ни его компонент меню. ServerPanelBridge должен остаться в серверном INI, а ServerPanelBridgeMenu туда добавлять не нужно.

Адаптер запускается через OnServerStarted до обработки подключений и затем через OnTickEvenPaused. При PauseEmpty=true обычный OnTick пропускается на пустом сервере: из-за ожидания этого события первому клиенту требовался мод. Теперь обработка работает и на паузе; это также позволяет выполнить разрешённую команду Stop на пустом сервере. Исключение ID из списка обязательных модов перепроверяется каждые пять секунд, даже если мониторинг выключен.

В стартовом логе сервера должна появиться строка:

```text
[ServerPanelBridge] Client optional mode confirmed: ServerPanelBridge removed from required mod list
```

Если её нет, проверь предшествующие ошибки ZombieBuddy и Java bridge. Остальные обязательные моды и проверка checksum сохраняются. Подключение реального клиента без ServerPanelBridge остаётся проверкой после установки.

Изолированный тест загрузчика и пакета подключения после сборки:

```powershell
.\installer\test-bridge.ps1 -GameDirectory "<папка ProjectZomboid>" -ZombieBuddyJar "<путь к ZombieBuddy.jar>"
```

Тест использует временный конфиг с выключенным мониторингом. Он не запускает и не останавливает игровой сервер, не меняет установленные моды.
## Перезапуск (0.3.0)

Помощник перезапуска встроен в тот же JAR и единый установщик. В активном конфиге сервера добавь:

```properties
commandsEnabled=true
restartEnabled=true
restartExitTimeoutSeconds=180
stopWhenPlayersOnline=false
```

После обновления и изменения конфига полностью перезапусти dedicated. Затем можно использовать Restart в ServerPanel. По умолчанию restartEnabled=false; этот переключатель независим от stopEnabled. Обе команды используют одну политику игроков: при stopWhenPlayersOnline=false занятый сервер откажет. Предупреждения в чат и обратного отсчёта пока нет.

Фоновый поток восстанавливает путь Java, исходные параметры, рабочую папку и идентичность процесса. Он запускает отдельную небольшую JVM помощника из встроенного JAR. После подтверждения готовности игровой поток вызывает штатный QueueQuit и разрешает помощнику запуск. Помощник ждёт завершения именно старого процесса, затем один раз запускает новый. Если сервер не завершился за restartExitTimeoutSeconds (10–600 секунд), повторный запуск отменяется. Принудительного завершения нет. Ошибка подготовки, истёкшая команда или отказ по игрокам отменяют помощника без остановки сервера.

Параметры передаются через закрытый канал между процессами и не сохраняются в скриптах или журнале команд. В Windows исходная строка читается фиксированным запросом PowerShell/CIM с таймаутом; применяется [разбор аргументов Windows по документации Microsoft](https://learn.microsoft.com/en-us/cpp/c-language/parsing-c-command-line-arguments?view=msvc-170). Если восстановить запуск нельзя, команда отказывается до остановки сервера. Поддерживается прямой запуск Java с zombie.network.GameServer. Файлы аргументов (@...) и буквальные двойные кавычки внутри уже разобранного аргумента отклоняются. Пробелы, Unicode в путях и завершающие обратные слеши проверены.

Повторным запуском должен заниматься один компонент. Если уже настроен внешний автоматический перезапуск, оставь restartEnabled=false и используй его. Управление деревом процессов или Windows Job может завершить дочернего помощника; в таком случае нужен перезапуск через супервизор. Новый сервер работает от того же пользователя и наследует окружение. Его вывод дописывается в restart-console.log рядом с конфигом, результат помощника — в restart-helper.log. Эти два файла автоматически не ротируются. Интерактивного ввода в новую консоль нет; управление остаётся через панель и игровые средства.

Успех команды означает, что остановка запрошена и помощник активирован. Он не подтверждает сохранение мира или успешный запуск нового сервера. Проверь логи и возвращение heartbeat. Если сервер завершился до подтверждения панели, журнал защищает следующий запуск от повторного выполнения команды. Start по-прежнему требует внешнего управления процессом.

Изолированный тест помощника, без запуска настоящего игрового сервера:

```powershell
.\installer\test-restart.ps1 -JavaExecutable "<game jre64/bin/java.exe>"
```
## Диагностика перезапуска (0.3.1)

restart-helper.log теперь содержит этапы с датой, PID нового процесса и его итоговый код выхода в десятичном и шестнадцатеричном виде. Если процесс жив через десять секунд, помощник сообщает только это, без утверждения о готовности сервера. Помощник остаётся рядом для наблюдения за выходом; повторных запусков и завершения процесса он не делает. Возможность записи консольного лога проверяется до остановки старого сервера. Аргументы запуска в эти сообщения не попадают.

Если консольный лог обрывается на загрузке, а хост в панели не появился, сначала нужно отличить завершившийся процесс от продолжающейся или зависшей загрузки. Heartbeat начинается после инициализации серверного цикла. Последняя строка LOADING ASSETS: START сама по себе не доказывает ни падение, ни готовность. Сохрани restart-helper.log, restart-console.log и последний серверный DebugLog; при нативном сбое проверь hs_err_pid*.log в рабочей папке игры. Не запускай второй сервер с тем же сохранением и портами, пока не проверен PID нового процесса.
После выхода старого процесса помощник проверяет фактические GameServer.defaultPort и GameServer.udpPort попыткой эксклюзивного открытия UDP-портов. Он ждёт освобождения до 30 секунд, затем отменяет запуск, если порт недоступен. На Windows журнал содержит ownerPid, когда доступен Get-NetUDPEndpoint. Помощник не завершает владельца порта и не меняет порты. Если поля портов отсутствуют или некорректны, подготовка отклоняется до остановки сервера. Проверка консервативная и не резервирует порты: другой запуск может занять их уже во время загрузки игры. Перезапуском должен управлять один компонент.

Connection Startup Failed. Code: 5 означает SOCKET_PORT_ALREADY_IN_USE в [перечислении RakNet](https://github.com/facebookarchive/RakNet/blob/master/Source/RakNetTypes.h). Ищи ownerPid в restart-helper.log на машине дедикейтеда. При отмене повторного запуска старый сервер уже остановлен; устрани конфликт портов перед новым запуском.

## Исправление рестарта на Windows (0.3.2)

Прежний запуск через Java ProcessBuilder передавал помощнику открытые нативные сокеты RakNet. Старый сервер закрывал сокеты и завершался, но их унаследованные копии продолжали удерживать UDP-порты. Проверка в 0.3.1 замечала это, однако причину не устраняла.

Теперь встроенный Windows-компонент передаёт помощнику только каналы обмена данными, без сокетов старого сервера. Сам компонент выходит после завершения старого сервера или отмены помощника и освобождает свои копии. Помощник и новый сервер больше не наследуют старые сокеты. Принудительное завершение процессов и автоматические повторы не добавлены. Компонент встроен в JAR и общий установщик; он использует штатный .NET Framework, который уже нужен установщику. Отдельная установка не нужна. При подготовке файл извлекается в папку активного конфига с именем по хешу содержимого; ошибка извлечения или запуска отклоняет рестарт до остановки сервера.

Обнови мод общим установщиком при остановленном дедикейтеде, затем запусти сервер с новым JAR. Если от прежней версии остались зависшие процессы, их нужно отдельно идентифицировать: обновление их не завершает. Конфиг сохраняется. После полной загрузки сервера проверь Restart и возвращение хоста в панель.

Тест с установленными RakNet и Java, на временных портах, без загрузки мира и входа в Steam:

```powershell
.\installer\test-native-restart.ps1 -GameDirectory "<ProjectZomboid directory>"
```

Один и тот же тест воспроизводит занятые порты на коде 0.3.1 и успешный повторный запуск с открытием обоих портов на 0.3.2. Это проверка реальной сетевой библиотеки и механизма запуска, а не полного запуска рабочего мира. На Windows сборка встраивает компонент штатным компилятором .NET Framework; на других платформах остаётся прямой запуск Java-помощника.

## Поддержка ServerPanel 1.12–1.13 (0.4.0)

При каждом запуске JVM создаётся новый sessionId. Он один для heartbeat, опроса команд, ACK и Output, не записывается в конфиг и меняется после перезапуска сервера. Stop/Restart с чужим targetSessionId пропускаются ещё до подготовки помощника и резервирования команды. Срок действия команды expiresAtUtc и срок аренды leaseExpiresAtUtc проверяются до исполнения, включая проверку на игровом тике. Если действие начато вовремя, его результат можно подтвердить после истечения срока команды, пока аренда действительна. Ответы старых панелей без новых необязательных полей сохраняют прежнюю проверку аренды. Сеанс защищает от старых команд, но не заменяет аутентификацию.

После обновления открой у хоста вкладку **Output**: новые события моста передаются автоматически. Для вывода Java-консоли добавь в активный конфиг конкретного сервера и перезапусти его:

```properties
outputEnabled=true
captureConsoleOutput=true
```

Мод дублирует System.out/System.err, сохраняя исходные байты обычной консоли. Старые файлы, история чата, нативный C/C++ вывод и записи через сохранённые до подключения потоки не импортируются. Другие моды могут обходить или заменять эти потоки; при завершении мост восстанавливает их только если всё ещё владеет ими. Некоторые настройки логирования могут давать дубликаты. В консоли бывают IP-адреса игроков, чат и секреты; скрытие не гарантируется, а панель хранит текст открыто в БД и резервных копиях. Поэтому захват консоли по умолчанию выключен.

Отправитель Output работает отдельно: очередь до 500 записей, пакеты до 100, строка до 4000 символов UTF-16. При переполнении вытесняются старые записи. Незавершённая строка консоли занимает не более 16 КБ до перевода строки или очистки. Отправка начинается после успешного heartbeat. Ошибочные и зависшие пакеты не отправляются повторно: API панели не устраняет дубликаты. Это текущий вывод без гарантии доставки, импорта старых логов или отправки остатка при выходе; в панели остаются последние 500 записей. outputEnabled=false отключает оба источника. Существующий конфиг сохраняется; отсутствующие новые параметры получают указанные значения по умолчанию. Обнови мод единым установщиком и полностью перезапусти сервер.

Проверка с готовой сборкой ServerPanel, без запуска рабочего приложения и изменения его БД:

```powershell
dotnet run --project tools/PanelApiSmoke/PanelApiSmoke.csproj -c Release -p:PanelAssembly="<ServerPanel.App.dll path>" -- "<java.exe path>" "<bridge project root>"
```

Тест использует временный локальный порт, реестр в памяти, отдельные тестовые JVM и имитацию игровых действий. Реальные Output/UI и подключение игроков проверяются на рабочем сервере после установки.

## Автодополнение конфига (0.4.1)

После обновления просто запусти дедикейтед. Мост сравнит активный конфиг с новым шаблоном и допишет только отсутствующие параметры. Удалять старый файл ради новых опций больше не нужно. Существующие значения, комментарии, неизвестные пользовательские параметры, порядок строк, UTF-8/BOM и переводы строк сохраняются. Уже записанное значение не заменяется новым значением по умолчанию. Если все параметры есть, файл и его время изменения остаются прежними, новая копия не создаётся.

Перед изменением рядом сохраняется точная копия: `ServerPanelBridge.properties.backup-<уникальный номер>.bak`. Обновлённый файл сначала записывается во временный файл, затем атомарно заменяет исходный. При ошибке проверки, резервного копирования или замены исходный конфиг сохраняется, а инициализация сообщает об ошибке. Неправильные значения не исправляются молча. Редактируй конфиг при остановленном сервере: обнаруженное параллельное изменение отменяет обновление. Резервные копии содержат твои настройки, держи их приватными; автоматически они не удаляются.

Источник новых параметров — тот же шаблон с комментариями, который входит в установщик. Будущие опции также будут автоматически добавляться. Установщик по-прежнему сохраняет имеющийся конфиг; дополнение выполняется при запуске сервера, даже если отправка в панель выключена. После дополнения измени нужную опцию и перезапусти сервер для применения. Удалённая строка снова считается отсутствующей и восстанавливается со значением по умолчанию: чтобы выключить булеву опцию, явно поставь `false`.

## Необязательные запросы других модов (0.5.0)

Публичный JVM-local API: io.serverpanelbridge.ModRestartApi.apiVersion() = 1, requestRestart(requester, requestId), status(requester, requestId). Возвращаются QUEUED, ARMED или статусы REJECTED_/FAILED_. HTTP-доступа к этому API нет. ID запросов ограничены, повтор одного ID не запускает новый helper; до 128 результатов на JVM, один активный локальный запрос. Имя requester — административный allowlist, не защита от произвольного Java-кода внутри JVM.

Для Sentinel включите restartEnabled=true и restartRequesters=WorkshopSentinel. Пустой список по умолчанию отключает интеграции. stopWhenPlayersOnline сохраняет силу. Helper и журнал готовятся рабочим потоком; действие выполняется на игровом потоке через общий с командами панели gate. Ошибка подготовки не останавливает сервер. ARMED не подтверждает готовность нового сервера. Итоги локальных запросов пишутся в существующий журнал без HTTP ACK.

Интеграция не требует связи с панелью: enabled=false и commandsEnabled=false можно сочетать с явным разрешением restart и requester. Удалённые команды от этого не включаются. WorkshopSentinel не становится зависимостью Bridge и не встраивается в него. Оставляйте одного владельца рестарта; не запускайте второго супервизора для того же процесса.

## Общий контракт для модов (0.5.1)

Другие серверные моды используют тот же версионированный [Local restart API v1](docs/MOD_RESTART_API.md): через Java reflection или Lua-глобальную таблицу ZombieBuddy. В рабочем коде нет отдельных веток для Sentinel и обязательной зависимости от него. В restartRequesters можно разрешить несколько точных имён. Любой запрос проходит действующую проверку игроков, общую очередь, помощника и журнал Bridge; обойти эти проверки через API нельзя.

Одновременные повторы одного запроса получают один результат и не создают лишних помощников. Срок локального запроса — 60 секунд с момента приёма, включая ожидание рабочего потока. При закрытии Bridge ожидающие запросы получают конечный статус. Существующий Java-адаптер Sentinel совместим с API v1 и не требует специального маршрута.

Для Lua доступны ServerPanelBridge.restartApiVersion(), requestRestart(requester, requestId) и restartStatus(requester, requestId). Отправитель сохраняет ID для повторов одной операции, проверяет доступность/версию API и не запускает второй механизм рестарта при отказе. ARMED означает только запрос штатной остановки и активацию помощника; успешная загрузка нового сервера этим не подтверждается. Локальные интеграции работают без связи с панелью при явном restartEnabled=true и разрешённом имени отправителя.
