# Integration boundaries

ZombieBuddy registers LuaBridge under the distinct alias ServerPanelBridge. Dedicated-server OnServerStarted initializes the bridge; OnTickEvenPaused maintains monitoring and command dispatch even when PauseEmpty pauses simulation. PzRuntime isolates game reflection. PanelReporter supplies heartbeat data from JVM APIs on its own daemon thread. OptionalClientAdapter removes only the advertised core-mod ID after loading, before the server handles connections. It rechecks every five seconds, including disabled-reporting mode, and retries failed exclusions with bounded logging. The loaded runtime list remains intact.

ServerPanelBridgeMenu is an optional local administrator component kept outside the core mod, so its client Lua is not included in server checksums. The installer enables it in the client profile only. Its MLOS adapter retains installed local ServerPanelBridge without inventing a Workshop ID.

## Command processing (0.2.0)

CommandService has a separate daemon worker: GET /api/hosts/{id}/commands leases commands, POST .../{commandId}/ack includes the current leaseToken. Responses have a 128 KiB size limit, bounded completion time and strict JSON parsing. Game callbacks do no HTTP or journal work. Restart arming writes one byte into the already-drained helper pipe after QueueQuit.

Stop requires stopEnabled; restart independently requires restartEnabled. Start, unknown actions and disabled controls produce failure acknowledgements. Expired leases cannot execute. At most eight commands are considered per poll; other leases are eventually delivered again by the panel. Heartbeat stays on a separate scheduler.

Before queuing stop, an atomic journal reservation is flushed to disk. A game tick checks the lease and calls ShutdownAdapter. PzShutdownAdapter probes GameServer.server, getPlayerCount(), ServerMap.instance and void QueueQuit(). It rejects occupied servers unless stopWhenPlayersOnline=true. No unsupported-API fallback or process kill exists.

Completion is recorded and acknowledged asynchronously. Success reports a queued shutdown request, not save or exit completion. If the process exits before acknowledgement or journal completion, the reservation prevents replay against the next JVM session and reports an uncertain outcome on redelivery. Journal IDs are validated, bounded to 1,000 records, and contain no lease tokens. Journal write failure prevents action; completion-write failure retains the pending result for retry.

The installer preserves runtime configuration and journal. Process start/recovery remains outside the mod. A full live server shutdown remains a deployment test; automated checks use a fake game action and temporary panel with memory storage.

## Bundled restart helper (0.3.0)

JvmRestartAdapter prepares RestartHelper on the command worker only after a durable reservation. It validates the executable/main class, captures arguments through ProcessHandle or a fixed Windows CIM query, then sends the launch specification through stdin. No launch arguments enter the journal or a persistent script. Helper readiness is bounded; unsupported metadata/argument forms reject preparation before game action. Literal quotes and argument files are refused to avoid ambiguous replay. Pending game actions are capped at eight.

The game callback rechecks lease, helper liveness and existing shutdown state, applies the same PzShutdownAdapter player policy, requests QueueQuit and arms the helper. Cancellation closes the unarmed ticket. Only an armed helper waits for the parent PID and start identity to exit, with a bounded timeout; it also rejects an occupied/reused PID before launching. It relaunches once without killing a server or invoking a configurable shell. Replacement launch does not establish game readiness. Existing journal replay protection applies to both actions.

The external helper owns only a requested relaunch, not general recovery/start. An external auto-restart supervisor must not also relaunch the same JVM. Helper/console logs are separate, append-only runtime files; inherited environment and filesystem paths stay local. No active server or panel is modified by the test harnesses.
## Replacement observation (0.3.1)

The helper checks console-output permissions before signalling readiness. Arming is consumed with a bounded blocking read, preserving buffered authorization even if the parent exits quickly. After one launch it records the replacement PID, reports liveness after ten seconds without equating it with readiness, waits for exit and records decimal/hex exit status. It never restarts that replacement automatically. A failed launch is identified by stage and exception type only; launch arguments remain private.
Before helper preparation, the adapter captures the two public effective GameServer UDP fields and rejects missing/invalid values. After exact parent exit, exclusive wildcard probes wait up to 30 seconds before relaunch. Windows owner diagnostics use a bounded fixed Get-NetUDPEndpoint query containing only numeric ports, limited to 32 endpoints. No owner command lines or credentials are collected. Probes are conservative and release sockets immediately; they cannot guarantee availability later in game startup. Launch failure and unavailable ports cancel without killing or retrying.

## Windows native resource isolation (0.3.2)

JDK 25's [Windows ProcessImpl](https://github.com/openjdk/jdk/blob/jdk-25-ga/src/java.base/windows/native/libjava/ProcessImpl_md.c) uses unrestricted inheritable handles. Installed RakNet sockets survived parent shutdown/exit in a direct-child reproduction. A Windows launcher embedded in the JAR uses STARTUPINFOEX and [PROC_THREAD_ATTRIBUTE_HANDLE_LIST](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) to pass only the three private standard-stream handles to RestartHelper. Its own inherited server sockets are released when its wait on the original process or helper process completes. Java's Process object tracks this proxy; the proxy remains alive during readiness/arming and exits when the helper cancels or the old server exits. This preserves the pipe handshake and process arguments without persisting secrets or changing server-native handles. The helper's normal post-parent-exit port check also allows the proxy time to exit.

The launcher runs without a window and never kills processes. It opens the original process with SYNCHRONIZE only and closes its process/thread/attribute-list handles. A SHA-256 resource filename and comparison avoid replaying stale or changed launcher bytes. Preparation fails before QueueQuit if extraction or launch is unavailable. Windows packaging requires the built-in .NET Framework compiler; non-Windows launches remain direct. The native regression fixture opens both real RakNet UDP ports before helper preparation, closes them on original shutdown, and opens them again in the replacement.

## Current panel protocol (0.4.0)

ClientSession supplies one nonpersisted GUID-N per bridge/JVM. Heartbeat, commands query/ACK and output share it. CommandService retains independent action and lease deadlines: expired TTL or foreign target is rejected before journal reservation/helper preparation, then checked again on game tick. ACK uses the lease deadline alone. Missing optional TTL/target fields retain legacy compatibility. Existing journal replay protection and native-handle-isolated restarts are unchanged.

OutputReporter attaches a handler only to the bridge logger, optionally installs ConsoleCapture for Java streams, and queues bounded immutable records. Its independent daemon sends to /api/hosts/{id}/output only after heartbeat registration; there is no HTTP/disk work in capture or game callbacks beyond the original console's own existing writes. Queue size 500, batches 100, text length 4000, unfinished console bytes 16000; oldest queued records are discarded under pressure. HTTP/1.1, literal loopback/no proxy/no redirects, bounded completion, and no failed-batch replay. Output failures do not recursively log to their own handler. Cleanup removes the handler and restores owned streams without closing originals. Full console capture is opt-in and not redacted.

## Additive config migration (0.4.1)

ConfigFile loads /defaults/ServerPanelBridge.properties, packaged from the installer reference file by processResources. Java Properties parsing identifies present keys (including escaped keys, duplicate/colon syntax and continuations); UTF-8 is decoded strictly and an optional BOM is ignored only during parsing. A validated merged BridgeConfig is constructed before writes. Missing entries and their adjacent template comments are appended to the original bytes with the original newline style. Two separator newlines safely terminate a trailing continuation; reparsing must equal the merged properties exactly. Existing keys, including unknown keys, are never reserialized.

Complete files return without writes. For upgrades, a sibling temporary copy preserves supported original attributes, receives the new bytes and is flushed. A unique sibling .backup-*.bak is copied/flushed and verified against the original snapshot before an atomic replacement. Original changes detected before replacement abort. There is no non-atomic fallback or silent invalid-value reset; incomplete backups and temporary files are cleaned up, verified backups are retained. This is startup migration, not an editor lock or live reload. Backup/temp patterns are ignored by Git.
